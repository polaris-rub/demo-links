Von den Rohdaten zur Grafik

Der Weg, den ein Ereignis nimmt: vom xAPI-Statement, das ein Quellsystem an die Rights Engine schickt, über die Speicherung im Learning Record Store, die Auswertung durch eine Analytic Engine, bis zur fertigen Grafik im Moodle-Dashboard.

Der Weg im Überblick

1

Event speichern

Ein Quellsystem (z. B. Moodle) schickt ein xAPI-Statement an die Rights Engine.

2

Einwilligung prüfen

Die Rights Engine prüft Verb und Kontext gegen die Einwilligung. Gespeichert wird, wenn eine gültige Einwilligung vorliegt oder das Verb ausdrücklich als nicht einwilligungspflichtig markiert ist. Fehlt beides, wird das Statement je nach Konfiguration abgelehnt oder anonymisiert gespeichert.

3

Analytic Engine fragt an

Die Engine fragt bei der Rights Engine an: „Gibt es Daten für diese Analyse?“

4

Rohdaten abrufen

Die Rights Engine prüft die Berechtigung der Engine, fragt die passenden Rohdaten im LRS ab und liefert sie zurück.

5

Ergebnis berechnen & speichern

Die Analytic Engine berechnet das Ergebnis und schreibt es in den Result Store – zusammen mit Metadaten wie Engine-Name, Nutzer-ID und Zeitraum.

6

Dashboard lädt & rendert

Das Dashboard fragt den Result Store ab, ordnet die Daten den jeweiligen Grafiken zu und zeigt sie an. Liegen keine Ergebnisse vor, erscheint „Keine Daten“.

So wird eine neue Auswertung eingerichtet

1. Datenbündel in der Rights Engine anlegen

Im Tab „Quellsysteme“ wird festgelegt, für welche xAPI-Verben eine Einwilligung nötig ist. Nur aktivierte Verben stehen später für Analysen zur Verfügung. Ein Datenbündel bezieht sich immer auf genau ein Quellsystem.

2. Analyse (AnalyticEngine) anlegen & Verben auswählen

Im Tab „Analysen“ wird die Analytic Engine als eigener Eintrag registriert. Wichtig: Es müssen auch hier die Verben ausgewählt werden, die die Engine auswerten soll – dieselben, die im Datenbündel freigegeben wurden.

3. Analytic Engine per Docker starten

Die Engine läuft als eigener Docker-Container (Quelle: engine_scheduler_update/ in polarisdemo). In der docker-compose.yml wird der Pfad zum jeweiligen Engine-Verzeichnis eingetragen, API-URL und Token kommen aus der Rights Engine in die .env-Datei.

Nützliche Docker-Befehle (im Verzeichnis engine_scheduler)

docker compose up -d        # Container starten
docker compose ps           # Status anzeigen
docker compose logs -f <name>  # Fehler live beobachten

4. Dashboard in Moodle konfigurieren

Im Plugin local_polaris_rwth werden API-URL, Token und die Namen der Analytic Engines eingetragen (kommagetrennt, ohne Leerzeichen). Eingebunden werden die Grafiken in moodlesrc/local/polaris_rwth/templates/dashboards.mustache.
